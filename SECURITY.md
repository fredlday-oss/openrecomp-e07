# Security policy

OpenRecomp treats parser, translation, memory-boundary and public-evidence issues as security-relevant engineering concerns.

Do not place credentials, private account data, authentication logs, proprietary binaries or other sensitive material in a public issue.

For a vulnerability that can safely be discussed publicly, open a GitHub issue with a minimal redistributable reproduction.

For a sensitive vulnerability, use GitHub's private vulnerability reporting feature if it is enabled for this repository. If private reporting is unavailable, do not publish exploit-sensitive or private data merely to create a report.

Security fixes should include regression coverage where practical and should preserve the project's PROVEN/CANDIDATE distinction.
