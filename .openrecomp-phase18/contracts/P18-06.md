# P18-06 - VRAM Mutation / Display State

## Purpose

Mechanically establish whether authentic graphics commands mutate VRAM or the
display configuration by the P18-05 continuation, and if they do, generate
deterministic evidence (VRAM mutation digest, bounded VRAM dump descriptor,
GPU command digest, display-start coordinates, display mode, framebuffer
coordinates/dimensions/digest, deterministic rendered artifact).  This stage
does **not** fabricate traffic and does **not** inject a command stream.

Because P18-04 and P18-05 established that the authentic continuation reaches
no GP0/GP1 write and no DMA-channel access, the honest primary outcome is an
explicit, evidence-backed **VRAM / DISPLAY FRONTIER NOT YET REACHED** verdict.
This stage must still prove that the VRAM/display model it applies to the
runtime is genuine and correct, so that "unreached" is a real frontier state
and not a missing implementation.

An image alone is not proof.  No displayable output is promoted;
`FIRST_FRAME_READY` stays `NO`.

## Hardware model (public PS1 hardware; no title constant)

- VRAM: 1024 x 512 pixels, 16 bits per pixel (1 MiB), little-endian words.
- GP0 drawing commands that mutate VRAM: `0x02` fill-rectangle,
  `0x80` VRAM-to-VRAM copy, `0xA0` CPU-to-VRAM copy, `0xC0` VRAM-to-CPU copy,
  and the polygon/line/rectangle primitive classes (`0x20`/`0x40`/`0x60`
  families).
- GP1 display-control commands: `0x03` display enable, `0x05` display-area
  start, `0x06` horizontal display range, `0x07` vertical display range,
  `0x08` display mode.
- Framebuffer geometry is derived from the display-area start and the display
  mode's horizontal resolution field; no title constant is used.
- All coordinates are 10-bit VRAM coordinates; out-of-range or unaligned
  addresses/regions fail closed.

## Implementation boundary

- New module `.openrecomp-phase18/src/p18_vram_display_v1.py` and a new gate

  produced words into the model, proving the model applies to the emitted

## PASS conditions

The stage PASSES when **either** outcome is legitimately established:

1. **VRAM / DISPLAY FRONTIER NOT YET REACHED** (expected primary outcome):
   - the continuation reaches GPUSTAT reads and BIOS dispatch but **zero**
     GP0/GP1 writes and **zero** DMA-channel accesses, so no authentic graphics
     command mutates VRAM or display state;
   - the generated runtime is shown to contain the genuine, window-gated GPU
     write path (P18-04 discipline) plus the DMA-window tap (P18-05), so
     "unreached" is a real frontier state;
   - the deterministic VRAM/display model is exercised by positive controls
     (a fill, a CPU-to-VRAM copy and a display-enable/start sequence mutate the
     model deterministically, producing stable VRAM and framebuffer digests);
   - a controlled probe compiled against the official generated runtime source
     drives the generated GPU write entry points, and the produced words are
     applied to the model, yielding deterministic VRAM/display evidence;
   - the displayed-framebuffer artefact descriptor is recorded but is explicitly
     NOT promoted as a frame (no `FIRST_FRAME_READY` change).

2. **MUTATION OUTCOME** (when authentic GP0/GP1 traffic occurs):
   - every reached GP0/GP1 write binds to sequence, guest PC, authenticated
     owner provenance digest, physical address, width and an opaque word digest;
   - VRAM mutation is recorded as a deterministic digest and a bounded region
     descriptor; the display configuration is recorded from the actual register
     writes.

Common requirements for both outcomes:

- Official gate run twice: exit 0, empty stderr, byte-identical stdout (raw and
  LF), identical evidence artifacts.
- Negative controls fail closed.
- No title-specific constant; no injected command stream; no raw payload bytes.

## FAIL conditions

- Any check failure, non-zero exit, non-empty stderr, or non-identical dual-run
  output/artifacts.
- A VRAM mutation claimed without an authentic GP0/GP1 write; an out-of-range
  or unaligned VRAM region accepted; a hard-coded title value; unauthenticated
  owner; fabricated event; a promoted frame.

## NOT_PROVEN properties

- FIRST_FRAME_READY=NO; initialization / frame / playability / general PS1
  compatibility remain NOT_PROVEN.
- If the frontier is unreached, no authentic VRAM content or display
  configuration is established.

## Negative controls

- VRAM address outside `0x000000..0x0FFFFF` rejected `VRAM_ADDRESS_OUT_OF_RANGE`.
- Unaligned VRAM address rejected `VRAM_ADDRESS_UNALIGNED`.
- Fill-rectangle region exceeding VRAM bounds rejected `VRAM_REGION_OUT_OF_RANGE`.
- Display-start coordinates outside the VRAM coordinate space rejected
  `DISPLAY_START_OUT_OF_RANGE`.
- Unknown GP1 display command rejected `GP1_COMMAND_UNSUPPORTED`.
- Unknown GP0 command word classified `UNKNOWN`, never a no-op.
- A model event without an authenticated owner rejected.
- An empty VRAM frontier without an explicit NOT_REACHED status rejected.
- Controlled probe: driving the generated GPU write entry points produces real
  GPU-write events, and the model produces a non-empty, deterministic mutation
  digest (proves the model is genuine, so the unreached frontier is real).

## Determinism requirements

- Official gate run twice; byte-identical stdout (raw and LF), empty stderr,
  exit 0, identical evidence artifacts.
- Independent fresh-private-root reproduction byte-identical to official
  evidence.
