# P18-04 - GPU Command Frontier

## Purpose

Mechanically establish whether authentic GP0/GP1 GPU command traffic is reached
by the P18-03 continuation, and if it is, decode and classify the reached
commands.  This stage does **not** fabricate traffic and does **not** hardcode a
command stream.  Its legitimate primary outcome may be an explicit,
evidence-backed **COMMAND FRONTIER NOT YET REACHED** verdict; the decoded-command
outcome is the alternative when GP0/GP1 traffic genuinely occurs.

Both outcomes fail closed: an unknown command word is never silently treated as
a valid no-op, and an unknown/unmodelled write is always reported as
`UNSUPPORTED`/`UNCLASSIFIED` rather than assumed benign.

## Prerequisites

- Frozen Phase-17 terminal authority (tag/commit/tree as in P18-02/P18-03).
- P18-00 PASS, P18-01 PASS (`STATE_DRIVEN_BIT26`), P18-02 PASS (authentic poll
  exit), P18-03 PASS (causal device transcript).
- Committed P17-06R device transcript digest
  `d7e222c87726748ced23dd60c2b1ba138625227c984dac587be6a5761695fd3a`.
- Private Hercules fixture present and hash-matched (fail closed otherwise).

## Provenance requirements

- Every reached instruction and every reached GP0/GP1 address derives from
  authenticated bytes; the raw FIFO word is never emitted (it is bound by an
  opaque digest, exactly as in P18-03).
- The frontier determination is computed from the emitted runtime's own
  trajectory plus the generated source, never from a title constant.

  overlays, extending the emitted runtime with a GP0/GP1 command-FIFO tap and a

## PASS conditions

The stage PASSES when **either** outcome is legitimately established:

1. **COMMAND FRONTIER NOT YET REACHED** (expected primary outcome):
   - the continuation reaches GPUSTAT reads and BIOS dispatch but **zero** GP0
     and **zero** GP1 writes to `0x1f801810` / `0x1f801814`;
   - the generated runtime is shown to contain the GP0/GP1 write path
     (`or_p18_gpu_write`) gated on exactly those physical addresses, so the
     frontier is unreached because no reached instruction materialises that
     window - not because the path is missing;
   - GP0/GP1 are listed as explicitly NOT_REACHED (never a silent no-op);
   - every other reached category is listed with an authenticated owner.

2. **DECODED COMMAND OUTCOME** (when GP0/GP1 traffic occurs):
   - every reached GP0/GP1 write binds to sequence, guest PC, authenticated
     source owner provenance digest, decoded instruction, physical address,
     width and an opaque word digest;
   - each command is classified into an explicit class set;
   - any word not matching a declared class is reported `UNKNOWN` and the stage
     result records the unsupported count; it is never treated as a no-op.

Common requirements for both outcomes:

- Official gate run twice: exit 0, empty stderr, byte-identical stdout (raw and
  LF), identical evidence artifacts.
- Negative controls fail closed.
- No title-specific constant; no hardcoded command stream.

## FAIL conditions

- Any check failure, non-zero exit, non-empty stderr, or non-identical dual-run
  output/artifacts.
- A GP0/GP1 write observed but not decoded/classified; an unknown command word
  silently discarded; the write path absent while the frontier is claimed
  unreached; hard-coded title value; unauthenticated owner; fabricated event.

## NOT_PROVEN properties

- FIRST_FRAME_READY=NO; initialization / frame / playability / general PS1
  compatibility remain NOT_PROVEN.
- DMA / ordering-table traversal, VRAM mutation and display configuration remain
  NOT established (P18-05..P18-06).

## Negative controls

- Unknown GP0 command word classified `UNKNOWN`, never a no-op.
- GP0/GP1 write to the wrong physical address rejected `WRITE_NOT_GP0_GP1`.
- GP0/GP1 event without an authenticated owner rejected.
- Tampered word digest rejected.
- GP0/GP1 window `UNREACHED` declared for a non-window address rejected.
- Write-path control: rewriting one executed memory-access site to the GP0/GP1
  window produces real GP0/GP1 events (proves the model is genuine and that the
  frontier is a genuine unreached state, not a missing path).

## Determinism requirements

- Official gate run twice; byte-identical stdout (raw and LF), empty stderr,
  exit 0, identical evidence artifacts.
- Independent fresh-private-root reproduction byte-identical to official
  evidence.
