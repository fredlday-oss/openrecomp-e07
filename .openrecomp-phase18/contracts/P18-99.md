# P18-99 - Terminal Phase 18 Closure

## Purpose

Mechanically audit the **complete certified Phase-18 stage chain** and, only if
that audit passes on every dimension, emit the canonical Phase-18 terminal
closure marker.

This stage is a **read-only terminal-closure stage**. It fabricates no guest
traffic, injects no command stream, mutates no VRAM, renders no image, and runs
no guest binary. It writes only its own evidence directory and reads the
committed corpus. It never modifies certified upstream evidence.

A terminal Phase 18 `PASS` means exactly one thing: *the Phase-18 evidence chain
is internally consistent, reproducible, and bound to the frozen Phase-17
authority*. It does **not** promote any emulation proof.

## Terminal audit dimensions

Each dimension fails closed. A failure in any one is a `P18-99` `FAIL`, and no
terminal marker is emitted.

1. **Stage chain** — stages P18-00..P18-91 are present, ordered, contiguous, and
   each stage's declared `next_stage` equals the certified successor
   (P18-91's successor is `P18-99`).
2. **Per-stage markers** — every stage emits its own `OPENRECOMP_P18_xx=PASS`.
3. **Provenance** — every stage's `RESULT.json` is byte-identical to the blob
   recorded at the commit that last modified it, and that commit is an ancestor
   of the certifying P18-91 commit. No evidence drift.
4. **Determinism records** — every stage carries a `determinism.json` whose
   recorded gate digest equals the live gate file's digest.
5. **Prior-phase integrity** — Phase 1..17 trees are unmodified versus the
   frozen Phase-17 terminal commit, and clean in the working tree.
6. **Manifest exactness** — as preconditions.
7. **Marker ledger** — protected claim markers are `NOT_PROVEN` and
   `FIRST_FRAME_READY=NO` in every stage result; historical Phase-17 markers
   preserved verbatim.
8. **Frontier-digest coherence** — the P18-04/05/06 frontier digests agree
   between producer `.sha256` files, the artifacts themselves, and the P18-07
   consumer.
9. **Public safety** — no private host path or reconstructive key in any stage
   evidence; prose findings reported, never masked.
10. **Control-document agreement** — `STATE.md`, `STAGE_QUEUE.md` and
    `HANDOFF.md` agree with the certified machine results on stage status and
    never promote a protected marker.
11. **HEAD/tree binding** — the tree is clean and HEAD descends from the
    certifying P18-91 commit.
12. **Negative controls** — the audit's own tamper detection is asserted
    positively, not merely asserted absent.

## Negative controls

Each must be demonstrated to *detect* the tamper, individually:

- A stage whose `RESULT.json` is edited after certification is detected as
  `PROVENANCE_DRIFT`.
- A stage whose recorded gate digest does not match the live gate is rejected
  `GATE_DIGEST_MISMATCH`.
- A manifest entry whose digest is wrong is rejected `MANIFEST_DIGEST_MISMATCH`.
- A manifest entry removed or added is rejected
  `MANIFEST_SET_MISMATCH` / `MANIFEST_UNEXPECTED_ENTRY`.
- A protected claim marker set to `PASS` is rejected `PROTECTED_MARKER_PROMOTED`.
- A `FIRST_FRAME_READY=PASS` in a stage result is rejected
  `FIRST_FRAME_PROMOTED`.
- A missing stage evidence directory is rejected `STAGE_EVIDENCE_MISSING`,
  never skipped.
- A control document disagreeing with the certified results is rejected
  `CONTROL_DOCUMENT_DISAGREEMENT`.
- A frontier digest that no longer matches its producer is rejected
  `FRONTIER_DIGEST_DISAGREEMENT`.
- An all-stages-appear-terminal control vector must **not** be treated as proof:
  the gate fails closed if a control vector with an unproven stage reads as
  terminal.

## Determinism requirements

- Official gate run twice through the Phase-18 stage runner: byte-identical
  stdout (raw and LF), empty stderr, exit 0 both runs, identical tests JSON and
  byte-identical evidence artifacts.
- The terminal marker is emitted by the gate only after all twelve dimensions
  pass, and is identical across both official runs.

## Proof boundaries

`OPENRECOMP_PHASE18_TERMINAL_V1=PASS` asserts only terminal closure of the
Phase-18 evidence chain. It does **not** establish:

- a rendered or valid first frame,
- PS1 title bootability or playability,
- general PS1 hardware compatibility,
- correctness of any emulation beyond the bounded frontiers already certified.

Terminal closure must never be read as first-frame readiness.
