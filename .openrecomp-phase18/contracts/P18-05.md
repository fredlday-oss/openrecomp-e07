# P18-05 - DMA / Ordering-Table Frontier

## Purpose

Mechanically establish whether authentic GPU DMA or ordering-table activity is
reached by the P18-04 continuation, and if it is, capture it: channel, MADR,
BCR, CHCR, direction, linked-list addresses, packet sizes, packet words,
resulting GP0 words and the termination condition.  This stage does **not**
fabricate traffic and does **not** inject a command stream.  Its legitimate
primary outcome may be an explicit, evidence-backed **DMA / OT FRONTIER NOT YET
REACHED** verdict, exactly as P18-04 established for the GP0/GP1 window; the
capture outcome is the alternative when DMA activity genuinely occurs.

Both outcomes fail closed: malformed, unaligned, cyclic or unbounded structures
are rejected with stable codes, and an unreached channel is always reported
`NOT_REACHED` rather than silently treated as a valid no-op.

## Provenance requirements

- Every reached DMA access derives from authenticated bytes; the raw register
  value is never emitted (it is bound by an opaque digest, exactly as in
  P18-03/P18-04).
- The frontier determination is computed from the emitted runtime's own
  trajectory plus the generated source, never from a title constant.

## Hardware model (public PS1 hardware; no title constant)

- DMA register window `0x1f801080..0x1f8010ff`; eight 0x10-byte channels
  (`2 = GPU`, `6 = OTC`).  Per channel: `+0x0 MADR`, `+0x4 BCR`, `+0x8 CHCR`.
- `CHCR`: bit 0 direction (0 = to main RAM, 1 = from main RAM), bit 1 step,
  bit 8 chopping, bits 9-10 chop size, bits 16-18 sync mode (0 manual,
  1 request, 2 linked list, 3 reserved), bit 24 start/busy, bit 28 trigger.
  Sync mode 3 (reserved) fails closed.  Channel register offset `+0xC` is
  reserved and is always recorded as `UNUSED`, never treated as a modelled
  command.
- Linked list: a node word with bit 23 set terminates the list; otherwise bits
  0-23 (masked `0x1ffffc`) are the next node address.  Traversal is bounded
  (node cap), alignment-checked (4-byte) and cycle-checked; each node's first
  word is classified with the P18-04 GP0 classifier.

## PASS conditions

The stage PASSES when **either** outcome is legitimately established:

1. **DMA / OT FRONTIER NOT YET REACHED** (expected primary outcome):
   - the continuation reaches GPUSTAT reads and BIOS dispatch but **zero**
     accesses (read or write) to any DMA channel register;
   - the generated runtime is shown to contain a genuine DMA-window tap gated
     on exactly `0x1f801080..0x1f8010ff`, plus the common physical-address
     reducer covering the hardware window, so the frontier is unreached
     because no reached instruction materialises that window - not because the
     path is missing;
   - every DMA channel is listed explicitly `NOT_REACHED`;
   - the bounded ordering-table traversal model is exercised by positive and
     negative controls;
   - a controlled probe compiled against the official generated runtime source
     drives the generated DMA entry points and produces real DMA-frontier
     events (channel 2 MADR/BCR/CHCR and a linked-list start), proving the
     path, tap and decoder are genuine.

2. **CAPTURE OUTCOME** (when DMA traffic occurs):
   - every reached DMA access binds to sequence, guest PC, authenticated owner
     provenance digest, channel, register, physical address, width and an
     opaque value digest;
   - linked-list chains are traversed with alignment, bound and cycle checks
     and each node word is classified; an unterminated or cyclic chain fails
     closed unless bounded handling is explicit.

Common requirements for both outcomes:

- Official gate run twice: exit 0, empty stderr, byte-identical stdout (raw and
  LF), identical evidence artifacts.
- Negative controls fail closed.
- No title-specific constant; no injected command stream.

## FAIL conditions

- Any check failure, non-zero exit, non-empty stderr, or non-identical dual-run
  output/artifacts.
- A DMA access observed but not decoded; an unaligned/cyclic/unbounded OT chain
  accepted; a hard-coded title value; unauthenticated owner; fabricated event.

  authentic path.

## Negative controls

- DMA register write to an address outside the window rejected
  `DMA_ADDRESS_NOT_IN_WINDOW`.
- Ordering-table traversal started at address zero rejected `OT_START_INVALID`.
- Unaligned MADR rejected `DMA_MADR_UNALIGNED`.
- Reserved CHCR sync mode rejected `DMA_SYNC_MODE_UNSUPPORTED`.
- OT chain with a cycle rejected `OT_CYCLE_DETECTED`.
- OT chain exceeding the node cap rejected `OT_TRAVERSAL_BOUND_EXCEEDED`.
- Ordering-table traversal started at an unaligned address rejected
  `OT_NODE_UNALIGNED`.
- DMA event without an authenticated owner rejected `EVENT_WITHOUT_PROVENANCE`.
- An empty DMA frontier with no explicit NOT_REACHED status rejected.
- Write-path control: driving the generated DMA entry points produces real
  channel-2 events (proves the model is genuine and the frontier is a genuine
  unreached state, not a missing path).

## Determinism requirements

- Official gate run twice; byte-identical stdout (raw and LF), empty stderr,
  exit 0, identical evidence artifacts.
- Independent fresh-private-root reproduction byte-identical to official
  evidence.
