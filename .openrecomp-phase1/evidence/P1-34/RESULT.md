# OPENRECOMP Phase 1 — P1-34 Evidence

Stage: `P1-34` — NES deterministic headless proof

Revision: working tree at HEAD `bd5f02f` (no commit created; additive untracked files).

## Scope delivered

- `tools/nes_headless_v1.py`: machine-backed 6502 reference
  (`NesReference6502`) that routes all data accesses through the P1-33
  `NesMachine` bus (RAM/mirrors, PPU, APU/IO, OAM DMA, controllers, mapper)
  while the decode image holds the mapped CPU address space; plus synthetic
  NROM program builders and the CPU-image mapper.
- `tools/test_nes_headless_v1.py` (`OPENRECOMP_NES_HEADLESS_V1=PASS`):
  - **differential proof**: an MMIO-free program (RAM, stack, ADC loop, JSR/RTS,
    JMP, KIL) run through the machine-backed reference and through
    frontend -> IR V1 -> Module Image V1 -> Core API yields identical
    A/X/Y/SP/P/PC, halted state and the full 64 KiB CPU address space
    (a=0xC6, pc=0x8032, halted);
  - **platform proof** (reference side, since NES CPU MMIO is memory-mapped):
    PPUCTRL=0x7E, PPUMASK=0x1E, VRAM $2000=0x11/$2001=0x22, OAM DMA page copy,
    controller read 0x41 (A+Right via $4016 strobe/shift), APU status 0x1F and
    frame counter 0x40;
  - NROM 16 KiB `$8000`/`$C000` mirroring vs 32 KiB identity;
  - deterministic repeatability (platform snapshot byte-identical across runs);
  - reset/IRQ/NMI entry through the cartridge vectors, with I-flag masking;
  - fail-closed write to the disabled I/O window ($4018);
  - secondary local-ROM metadata-only evidence.

## Semantic assumptions / documented sources

- CPU bus, PPU registers/memory, controller and OAM DMA: NESdev (as recorded in
  the P1-32/P1-33 evidence). The platform fixture is pinned on the reference
  side because CPU MMIO is memory-mapped on the NES, unlike the Master System
  port space used by the P1-23 proof.
- The differential fixture deliberately performs no MMIO so the 64 KiB address
  space comparison is exact; MMIO read side effects ($2002/$2007) are not
  applied while syncing the decode image.
- Interrupt entry is tested directly through the reference reset/IRQ/NMI
  surfaces between instructions (cycle timing deferred, as in P1-23).

## Limitations / deferred

- No cycle-perfect PPU/APU; no sprite-0/overflow timing; NMI is not generated by
  PPU vblank timing (the reference exposes explicit `nmi()`).
- Non-NROM mappers classify but fail closed.
