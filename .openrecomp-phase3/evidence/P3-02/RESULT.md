## Ingestion model

- Neutral parser (`p3_elf_image_v1.parse_elf32`) rejects: invalid magic,
  truncated/oversized headers, unsupported class/endianness/ident version,
  bad table entry sizes, out-of-bounds/overflowing program/section tables,
  out-of-bounds section content, integer-overflowing ranges, impossible
  segment/section alignment, memory/file load-range overlap, `NOBITS`
  executable traps, `NOBITS` outside a zero-fill tail, malformed section-name
  tables, overlapping allocated sections, sections not matching exactly one
  load segment, and dynamic/relocation/hash/interpreter forms. Failures raise
  `ElfIngestError` with a stable code; no partial image is produced.
- MIPS policy (`p3_target_mips32_v1.MIPS32_O32`) adds `EM_MIPS`/`ET_EXEC`,
  `EF_MIPS_ABI_O32`, `EF_MIPS_ARCH_32`, non-PIC, word-aligned file-backed
  `.text` and in-`.text` entry validation.
- `GuestImage` is the sparse deterministic memory model. File-backed bytes,
  zero-fill memory, executable code, read-only data and writable data stay
  distinct; `read`/`read_u32`/`write` are bounds checked and reject unmapped
  addresses, 32-bit range overflow and writes to read-only regions. Load-time
  identity hashes are computed once and are unaffected by later writes.

## BSS / NOBITS proof

- `.bss` is `SHT_NOBITS` (type 8), flags `0x3`, vaddr `0x00004e30`, size 18416.
- Declared file offset 20008 (`0x4e28`) lies inside the file, but the declared
  file range ends at 38424 > 31184 (crosses EOF); the placement records
  `file_size = 0` and the image never reads file bytes for it.
- The bytes at the declared offset in the file are non-zero
  (`4c696e6b65723a204c4c442031382e31` sample, sha256
  `952db9951b11ceb50ce9dc5e4382e07bacd7cdc20c5954eac155a8bd98ea2a66`), yet the
  image range is exactly 18416 zero bytes with sha256
  `c7d9a61211afaf5d6daf6f796219e56bd345ec160378ce97d0cd5d9d8c3aea81`,
  identical to the hash of 18416 zero bytes.
- `.bss` occupies the final 18416 bytes of the 18424-byte zero-fill tail of the
  writable load segment.

## Bounds-checked access proof

- Reads: header region equals file bytes; first `.text` word equals the file
  word; a read spanning the file/zero-fill boundary (`0x4e20`, 32 bytes)
  returns file bytes then zeros; `.bss` read is all zero.
- Rejections: unmapped probes (`0x134`, `0x200`, `0x467c`, `0x467f`, `0x4df8`,
  `0x4dff`, `0x9620`, `0x20000`) are `UNMAPPED_ADDRESS`; `read(0xfffffff0, 32)`
  is `RANGE_OVERFLOW`; writes into `.text`/`.rodata` are `READONLY_VIOLATION`.
- Writes into `.data` and `.bss` succeed and are visible, while the recorded
  pristine load-time identity (`initial_bytes`, `content_sha256`) is unchanged.

## Limitations and claim boundary

P3-02 proves OpenRecomp can safely and deterministically ingest the audited
CoreMark ELF and construct its guest section/data image. It does not prove that
any CoreMark instruction is supported (the P3-01 unsupported classes remain
P3-03/P3-04 work), that CoreMark can be translated or run, or any arbitrary
ELF/MIPS32/PS1/PS2 compatibility. `COREMARK_STATUS=NOT_PROVEN`; the terminal
Phase-3 marker remains `NOT_PROVEN`.
